# Conexión SSH a instancias EC2

> Este apunte amplía la sección de SSH vista en **[6. EC2 Básico](6.%20EC2%20B%C3%A1sico.md)**, centrándose en los **comandos concretos** y en las **tres formas** de conectarse a una instancia: terminal nativa (OpenSSH), PuTTY y EC2 Instance Connect.

---

# ¿Qué necesito antes de conectarme?

Para conectarte por SSH a una instancia EC2 necesitas tres cosas:

1. **Un par de claves (key pair)**: una clave privada (que te quedas tú) y una pública (que AWS guarda en la instancia).
2. **La IP pública o el DNS público** de la instancia (`ec2-x-x-x-x.compute-1.amazonaws.com` o similar).
3. **El puerto 22 abierto** en el grupo de seguridad de la instancia, permitiendo el tráfico desde tu IP (o desde el rango de IPs de EC2 Instance Connect si usas esa opción).

---

# 1. Creación del par de claves (Key Pair)

## Opción A: Desde la consola de AWS

1. **EC2 → Network & Security → Key Pairs → Create key pair**.
2. Ponle un nombre (ej. `mi-clave-ec2`).
3. Elige el tipo:
   - **RSA**: compatible con OpenSSH y PuTTY.
   - **ED25519**: más moderno y seguro, pero **no compatible con PuTTY** en versiones antiguas.
4. Elige el formato del archivo privado:
   - **.pem**: para SSH nativo (Linux, macOS, Windows con OpenSSH).
   - **.ppk**: para PuTTY (Windows).
5. Al crearla, **AWS descarga automáticamente la clave privada** a tu ordenador. Este es el único momento en el que puedes obtenerla: **AWS no guarda una copia de la clave privada**, así que si la pierdes tendrás que crear un par nuevo.

> ⚠️ Si eliges `.pem` pero necesitas usar PuTTY más adelante, no pasa nada: se puede convertir con **PuTTYgen** (lo vemos en la sección de PuTTY).

## Opción B: Generar el par de claves tú mismo (más control)

También puedes generar el par de claves localmente con `ssh-keygen` e **importar solo la clave pública** a AWS (así la clave privada nunca sale de tu máquina, ni siquiera pasa por los servidores de AWS).

```bash
ssh-keygen -t rsa -b 4096 -f ~/.ssh/mi-clave-ec2 -C "mi-clave-ec2"
```

Explicación del comando:

| Parte | Significado |
|---|---|
| `ssh-keygen` | Herramienta de OpenSSH para generar pares de claves |
| `-t rsa` | Tipo de clave (también válido `ed25519`) |
| `-b 4096` | Longitud de la clave en bits (más bits = más seguridad) |
| `-f ~/.ssh/mi-clave-ec2` | Ruta y nombre del archivo de salida (genera `mi-clave-ec2` privada y `mi-clave-ec2.pub` pública) |
| `-C "mi-clave-ec2"` | Comentario/etiqueta para identificar la clave (no afecta a la seguridad) |

Después, sube la clave **pública** (`mi-clave-ec2.pub`) a AWS:

```bash
aws ec2 import-key-pair \
  --key-name "mi-clave-ec2" \
  --public-key-material fileb://~/.ssh/mi-clave-ec2.pub
```

## Permisos del archivo de clave privada

En Linux/macOS, SSH **rechaza claves con permisos demasiado abiertos**. Hay que restringirlos justo después de descargar/generar la clave:

```bash
chmod 400 mi-clave-ec2.pem
```

| Comando | Qué hace |
|---|---|
| `chmod` | Cambia los permisos de un archivo |
| `400` | Solo el propietario puede **leer** el archivo (nadie puede escribir ni ejecutar) |

> Este es el fix del error clásico **"Unprotected private key file"** o **"Permissions 0644 for key are too open"**.

En **Windows**, si usas OpenSSH desde PowerShell/CMD, el equivalente es quitar herencia y dejar solo tu usuario con permiso de lectura:

```powershell
icacls "mi-clave-ec2.pem" /inheritance:r
icacls "mi-clave-ec2.pem" /grant:r "$($env:USERNAME):(R)"
```

# 2. Conexión por terminal (SSH nativo: Linux, macOS y Windows ≥ 10)

Windows 10 y versiones posteriores ya traen **OpenSSH** integrado en PowerShell/CMD, así que el comando es idéntico en los tres sistemas.

## Comando básico

```bash
ssh -i /ruta/mi-clave-ec2.pem ec2-user@ec2-XX-XX-XX-XX.compute-1.amazonaws.com
```

| Parte | Significado |
|---|---|
| `ssh` | Cliente SSH que inicia la conexión remota |
| `-i /ruta/mi-clave-ec2.pem` | Indica **qué clave privada** usar para autenticarse (identity file) |
| `ec2-user` | Usuario por defecto de la AMI (varía según el sistema operativo, ver tabla abajo) |
| `@ec2-XX-XX-XX-XX...` | IP pública o DNS público de la instancia |

## Usuario por defecto según la AMI

| AMI / distribución | Usuario por defecto |
|---|---|
| Amazon Linux / Amazon Linux 2 / 2023 | `ec2-user` |
| Ubuntu | `ubuntu` |
| Debian | `admin` |
| RHEL | `ec2-user` o `root` |
| Fedora | `fedora` |
| SUSE | `ec2-user` o `root` |
| Windows Server | (no aplica SSH nativo salvo que lo configures; se usa RDP) |

> Usar el usuario equivocado es la causa más común del error **"Permission denied (publickey)"**.

## Simplificar la conexión con `~/.ssh/config`

En vez de escribir el comando completo cada vez, puedes crear/editar `~/.ssh/config`:

```
Host mi-instancia
    HostName ec2-XX-XX-XX-XX.compute-1.amazonaws.com
    User ec2-user
    IdentityFile ~/.ssh/mi-clave-ec2.pem
    Port 22
```

Y luego conectarte simplemente con:

```bash
ssh mi-instancia
```

## Comandos útiles relacionados

| Comando | Qué hace |
|---|---|
| `ssh-add ~/.ssh/mi-clave-ec2.pem` | Añade la clave al **agente SSH** (`ssh-agent`) para no tener que indicar `-i` cada vez en esa sesión |
| `eval "$(ssh-agent -s)"` | Arranca el agente SSH en segundo plano |
| `scp -i mi-clave-ec2.pem archivo.txt ec2-user@IP:/home/ec2-user/` | Copia un archivo local **hacia** la instancia (Secure Copy) |
| `scp -i mi-clave-ec2.pem ec2-user@IP:/ruta/archivo.txt .` | Copia un archivo **desde** la instancia a tu máquina local |
| `sftp -i mi-clave-ec2.pem ec2-user@IP` | Abre una sesión de transferencia de archivos interactiva (SFTP) |
| `ssh -v -i mi-clave-ec2.pem ec2-user@IP` | Modo **verbose**: muestra el detalle de la negociación SSH, útil para depurar errores de conexión |

# 3. Conexión mediante PuTTY (Windows)

PuTTY es necesario en versiones antiguas de Windows (< 10) que no traen cliente SSH nativo, aunque también puede usarse en Windows 10/11 por preferencia.

## Paso 1: Descargar PuTTY y PuTTYgen

Ambos se descargan del sitio oficial: https://www.putty.org/

- **PuTTY**: el cliente SSH con interfaz gráfica.
- **PuTTYgen**: convierte claves `.pem` (formato OpenSSH) a `.ppk` (formato propio de PuTTY), ya que PuTTY no entiende `.pem` directamente.

## Paso 2: Convertir la clave `.pem` a `.ppk` con PuTTYgen

1. Abrir **PuTTYgen**.
2. Click en **Load** y seleccionar el archivo `.pem` (cambiar el filtro a "All Files" porque por defecto solo busca `.ppk`).
3. Click en **Save private key** → guardar como `mi-clave-ec2.ppk`.
4. (Opcional) Puedes añadir una passphrase para proteger la clave localmente.

## Paso 3: Configurar la conexión en PuTTY

1. Abrir **PuTTY**.
2. En **Session**:
   - **Host Name**: `ec2-user@ec2-XX-XX-XX-XX.compute-1.amazonaws.com`
   - **Port**: `22`
   - **Connection type**: `SSH`
3. En el árbol de la izquierda, ir a **Connection → SSH → Auth → Credentials**.
4. En **Private key file for authentication**, seleccionar el archivo `.ppk` generado en el paso anterior.
5. (Opcional) Volver a **Session**, escribir un nombre en **Saved Sessions** y pulsar **Save** para no repetir la configuración cada vez.
6. Pulsar **Open** para iniciar la conexión.

## Herramientas asociadas a PuTTY

| Herramienta | Uso |
|---|---|
| **PuTTY** | Cliente SSH gráfico |
| **PuTTYgen** | Genera/convierte pares de claves (`.pem` ↔ `.ppk`) |
| **Pageant** | Agente SSH de PuTTY: mantiene la clave privada cargada en memoria para no pedirla en cada conexión |
| **PSCP / PSFTP** | Equivalentes a `scp`/`sftp` pero para el ecosistema PuTTY, usados desde línea de comandos |

# 4. Conexión mediante EC2 Instance Connect

Permite conectarte **desde el navegador**, sin necesidad de gestionar claves ni instalar nada localmente.

## Requisitos

- El **puerto 22** debe estar abierto en el grupo de seguridad (al menos para el rango de IPs de EC2 Instance Connect, que se puede consultar en https://ip-ranges.amazonaws.com/ip-ranges.json).
- La instancia debe tener instalado el paquete `ec2-instance-connect` (viene preinstalado en Amazon Linux 2/2023 y Ubuntu recientes).
- Necesitas permisos IAM para la acción `ec2-instance-connect:SendSSHPublicKey`.

## Cómo funciona

1. Vas a **EC2 → Instances → seleccionas la instancia → Connect → EC2 Instance Connect → Connect**.
2. AWS genera un **par de claves efímero**, sube la clave pública a la instancia mediante la API y la usa para autenticarte.
3. Esa clave pública **expira a los 60 segundos**, así que no queda ningún acceso permanente residual.
4. Se abre una terminal directamente en el navegador.

## También disponible por CLI

```bash
aws ec2-instance-connect send-ssh-public-key \
  --instance-id i-0123456789abcdef0 \
  --availability-zone us-east-1a \
  --instance-os-user ec2-user \
  --ssh-public-key file://mi-clave-temporal.pub
```

Esto envía una clave pública temporal a la instancia, y después puedes conectarte con `ssh` normalmente usando la clave privada correspondiente, durante la ventana de 60 segundos.

---

# 5. Comparativa de los tres métodos

| Método | Requiere clave persistente | Requiere instalar software | Funciona desde cualquier navegador | Ideal para |
|---|:---:|:---:|:---:|---|
| **SSH nativo (terminal)** | ✅ Sí (`.pem`) | ❌ No (viene con el SO) | ❌ No | Uso diario, scripting, automatización |
| **PuTTY** | ✅ Sí (`.ppk`) | ✅ Sí | ❌ No | Windows < 10, o preferencia por interfaz gráfica |
| **EC2 Instance Connect** | ❌ No (clave temporal, 60s) | ❌ No | ✅ Sí | Acceso puntual, rápido, sin dejar accesos abiertos |

# 6. Errores comunes y solución rápida

| Error | Causa habitual | Solución |
|---|---|---|
| 🛑 `Unprotected private key file` / `Permissions 0644 for key are too open` | Permisos del `.pem` demasiado abiertos | `chmod 400 mi-clave-ec2.pem` |
| 🛑 `Permission denied (publickey)` | Usuario incorrecto (ej. `root` en lugar de `ec2-user`) o clave equivocada | Verificar el usuario según la AMI y que la clave `-i` sea la correcta |
| 🛑 `Connection timed out` | Problema de red/grupo de seguridad | Revisar: puerto 22 abierto para tu IP, NACL no bloqueante, instancia con IP pública, ruta a Internet vía Internet Gateway |
| 🛑 `Host key verification failed` | La huella digital del host cambió (ej. se recreó la instancia con la misma IP) | Eliminar la entrada antigua de `~/.ssh/known_hosts` para esa IP/host |
| 🛑 `Unable to load key` (PuTTY) | Intentas cargar un `.pem` directamente en PuTTY | Convertir primero con **PuTTYgen** a `.ppk` |
| 🛑 `No supported authentication methods available` (Windows con PuTTY) | El servidor solo acepta autenticación por clave y no se ha indicado ninguna, o el usuario está mal | Confirmar usuario y adjuntar la clave `.ppk` en Connection → SSH → Auth |

# Conceptos clave para recordar

✅ La clave privada (`.pem`) **solo se puede descargar una vez**, en el momento de crear el key pair; AWS no la guarda.

✅ `chmod 400` es el comando que arregla el error de permisos del archivo de clave en Linux/macOS.

✅ El **usuario SSH** depende de la AMI: `ec2-user` (Amazon Linux/RHEL), `ubuntu` (Ubuntu), `admin` (Debian), `fedora` (Fedora).

✅ PuTTY **no entiende `.pem`**: hay que convertirlo a `.ppk` con **PuTTYgen** antes de usarlo.

✅ **EC2 Instance Connect** no necesita gestionar claves: usa una clave pública temporal que expira a los **60 segundos**.

✅ `scp` copia archivos completos por SSH; `sftp` abre una sesión interactiva de transferencia de archivos.

✅ Un **timeout** casi siempre es un problema de grupo de seguridad o red; un **rechazo de clave/usuario** es un problema de autenticación.

# Preguntas típicas de examen

### ¿Qué comando usarías para arreglar el error "Unprotected private key file"?

```bash
chmod 400 mi-clave-ec2.pem
```

---

### ¿Cuántas veces se puede descargar la clave privada de un key pair desde la consola de AWS?

**Una sola vez**, en el momento de la creación. AWS no conserva una copia de la clave privada.

---

### ¿Qué usuario por defecto usarías para conectarte por SSH a una instancia con Ubuntu?

**`ubuntu`**.

---

### ¿Por qué PuTTY no puede usar directamente un archivo `.pem`?

Porque PuTTY usa su propio formato de clave (`.ppk`); hay que convertir el `.pem` con **PuTTYgen** antes de poder usarlo.

---

### ¿Qué ventaja de seguridad tiene EC2 Instance Connect frente al SSH tradicional?

Usa una **clave pública temporal que expira a los 60 segundos**, en lugar de depender de un par de claves permanente y un puerto 22 abierto de forma indefinida a una IP fija.

---

### Un usuario recibe el error "Connection timed out" al intentar conectarse por SSH, ¿qué deberías revisar primero?

El **grupo de seguridad** de la instancia (que el puerto 22 esté abierto para su IP), y en segundo lugar el NACL, la IP pública de la instancia y la ruta hacia Internet (Internet Gateway).

---

### ¿Qué comando permite copiar un archivo local a una instancia EC2 por SSH?

```bash
scp -i mi-clave-ec2.pem archivo.txt ec2-user@IP:/ruta/destino/
```
